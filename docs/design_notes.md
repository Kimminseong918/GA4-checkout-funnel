# 분석 설계 노트

판단을 바꾼 지점과 그 이유를 기록합니다.

## 1. 질문의 변화

| 순서 | 질문 | 계기 |
|---|---|---|
| 현업 요청 | "블랙프라이데이 때 방문자가 크게 늘었는데, 성과 좋았던 거죠?" | |
| 1차 | 늘어난 방문이 구매로 이어졌나? (트래픽 희석 의심) | 요청에 숨은 가정 "방문 증가 = 성과" 검증 |
| 2차 | 비시즌 전환율 하락은 퍼널 어느 단계에서, 누구에게서 생겼나? | H1 기각: 시즌 성과는 좋았음 |
| 3차 | 시즌 신규 방문자의 결제 단계 이탈은 누구에게서, 왜 생기나? | H2 기각 + 신규/재방문 분해에서 시즌 신규의 결제 이탈 발견 |
| 4차 (최종) | 할인 기간 신규가 결제 화면에서 최종 금액을 보고 떠나는 것을 어떻게 줄이고, 어떻게 검증하나? | H4 기각(기기·국가 무관) + H4-b 지지(할인 주에 집중) |

## 2. 가설 이력

가설별 근거·판정 기준·결과·행동 계획은 `docs/hypotheses.md`. 요약: H1·H2·H2-s·H4 기각, H3·H4-b 지지, H6은 A/B 설계.

## 3. 정의와 선택

### 분석 단위: 세션
- 구매 결정은 한 번 방문 안에서 일어나고, 기간 비교가 깔끔하게 나뉨
- 사용자 기준은 3개월 동안 12월에 담고 다음 해 1월에 산 사람이 두 기간에 섞임

### 기간
- 시즌 11/23~12/18: 추수감사절 주간 시작 + 일별 구매 급증 / 배송 마감 후 급락
- 비시즌 1/5~1/31: 연휴가 끝난 평소 상태
- 휴일 12/19~1/4 제외: 배송 마감과 휴일 영향(전환율 0.84%)이 섞여 계절 효과와 구분 불가
- 시즌 전 11/1~11/22: 할인을 기다리는 구매 지연이 섞일 수 있어 민감도 확인에만 사용

### 구매 기준: 구매가 있었던 세션
- purchase 이벤트는 중복 기록이 있고, 주문 ID는 16%가 확인 불가

### 퍼널 단계
- 조회 → 구매 의도 → 결제 시작 → 결제 정보 → 구매
- add_shipping_info 제외: 결제 시작과 거의 항상 함께 발생해 새 정보 없음
- view_item_list 제외: 기록 누락

### 퍼널 방식: 엄격 기준 퍼널 → 최대 도달 기준
- 처음에는 단계 해석이 명확한 엄격 기준 퍼널로 시작
- 사전 기준: 단계를 건너뛴 구매 세션이 10% 이상이거나 기간별 비율이 다르면 재검토
- 결과: 30.7% / 24.9%로 두 조건 모두 해당 → 단계 전환율 왜곡 가능
- 원인 검증(이전 세션 장바구니)에서 15%만 설명되어 원인 특정 불가
- 어떤 원인이든 결제를 시작해 구매한 세션을 이탈로 세는 것은 틀린 처리
  → 장바구니 단계를 "구매 의도 표시"로 재정의하고 최대 도달 기준를 메인으로 채택
- 엄격 기준 퍼널은 민감도 확인용으로 유지: 하락 기여도 순위 동일

### 열린 퍼널을 쓰지 않은 이유
- 단계마다 따로 세면 분자와 분모가 다른 세션 집단이 되어 단계 전환율 해석 불가

### 단계 전환율을 핵심 지표로
- 누적 전환율은 앞 단계 하락이 뒤 단계에 모두 전파되어 어느 단계가 약해졌는지 보이지 않음

### 세션 전환율의 분모
- 상품을 보지 않은 방문도 분모에 포함 (업계 표준 정의, 유입 품질 문제가 드러남)
- 대신 조회 도달률과 조회 이후 단계 전환율로 분해해 두 원인을 구분

### 신규 방문: session_number = 1
- first_visit과 98.4% 일치, 모순 0건

### 판정 기준과 그 근거
| 기준 | 값 | 근거 |
|---|---|---|
| 통계적 유의성 | p < 0.05 | 차이가 우연이 아닌지 확인 |
| 실질적 크기 | 상대 차이 10% 이상 | 화면이나 정책을 바꿀 만큼 의미 있는 크기인지. 세션이 10만 개 이상이라 작은 차이도 유의하게 나오므로 크기 기준을 함께 둠 |
| 퍼널 정의 재검토 | 단계를 건너뛴 구매 세션 10% 이상 | 구매의 10분의 1 이상이 이탈자로 잘못 분류되면 단계 전환율 해석이 흔들림 |
| 주된 원인 판정 | 설명 비율 70% 이상 | 대부분(3분의 2 이상)을 설명해야 주된 원인이라고 말할 수 있음 |
- 결과를 보기 전에 해석 규칙을 먼저 정함
  (장바구니 이전 하락 → 계절 요인 / 이후 하락 → 개선 가능한 누수)

### 매출 지표의 분모: 구매 세션당 매출 vs 주문당 객단가
- 처음에는 매출 ÷ 구매 세션을 '객단가'라고 불렀으나, 분모가 구매 세션이라 정확히는 '구매 세션당 매출'
- KPI 트리(일 세션 × 세션 전환율 × 구매 세션당 매출 = 일 매출)는 전환율의 분자가 구매 세션이라 이 값을 써야 곱셈이 맞음
- A/B 가드레일은 한 번 주문할 때의 금액을 봐야 하므로 주문당 객단가(매출 ÷ 주문)를 쓰고, 기준값도 대상 집단(할인 기간 신규, 66.44)으로 따로 구함

### 매출 계산: 세션 내 MAX → 주문 단위
- 같은 주문의 중복 기록(335건)을 피하려고 처음에는 세션 내 MAX를 사용
- 한 세션에 주문이 2건 이상인 경우가 시즌 6.8%로 확인되어, MAX가 시즌 매출을 8% 과소 계산
- 세션 × 주문 번호 단위로 금액 하나씩 → 합산하는 방식으로 변경 (같은 주문의 중복은 한 번, 다른 주문은 모두)

### H4 이후 범위를 좁힌 과정
- H4(모바일·해외)가 기각되자 "시즌에만 생기는 요인"으로 질문을 바꿈
- 도착일 vs 가격 비교를 구분할 패턴을 결과 전에 정함 (마감 근처 하락 vs 할인 주 하락)
- 할인 주에 신규만 낮고 할인 후 회복 → 개선 대상을 "할인 기간 신규의 결제 정보 단계"로 좁힘
- 배송 정보 이벤트로 결제 화면 안의 이탈 위치를 더 좁히려 했으나, 이벤트가 결제 시작과 동시에 기록되어 포기

### A/B 핵심 지표를 바꾼 이유
- 처음에는 이탈이 일어난 단계의 전환율(결제 정보 ÷ 결제 시작)을 핵심 지표로 정함
- 개선안은 그보다 앞인 장바구니에서 개입하므로, B안을 본 사람 중 가격만 확인하려던 사람은 결제를 시작하지 않게 되어 분모가 달라짐
- 구매가 늘지 않아도 지표가 오르는 착시가 생기므로, 핵심 지표를 개입 지점부터의 구매 전환율(구매 ÷ 장바구니 도달)로 변경
- 기존 지표는 효과가 어느 단계에서 생겼는지 해석하는 진단 지표로 둠
- 기준값이 41.9% → 15.1%로 낮아져, 할인 기간 21일로 검출 가능한 효과가 상대 +14% → +20%로 커짐 (정확한 지표를 위해 감수)

### A/B는 실행하지 않고 설계로 제시
- 공개 데이터라 화면 변경·무작위 배정·트래픽이 없어 실행 불가
- 실무에서도 분석가는 설계와 결과 분석을 맡으므로, 설계(대상, 지표, 기준값, 표본 수, 기간, 판단 규칙)까지를 범위로 정함
- 실제 실험 결과 분석은 P4(무작위 배정된 프로모션 실험 데이터)에서 진행

### 생존분석을 쓰지 않은 이유
- 질문이 "시간이 지나며 사건이 일어나는가"가 아니라 "한 방문 안에서 단계를 통과했나"라서 비율 비교가 맞음
- 데이터가 3개월이고 사용자 ID가 쿠키 기준이라 장기 추적에도 부적합 → P2(재구매까지 시간)에서 사용

### 시각화 도구: Tableau
- 국내 공고에서 Tableau 요구가 더 많고 P2·P3에서도 이어서 사용 가능
- Tableau Public은 BigQuery에 직접 연결되지 않아 집계표를 CSV로 내보내 연결 (과거 데이터라 자동 갱신은 필요 없음)

## 4. 민감도 확인

"고른 정의나 기준을 바꿔도 결론(비시즌 하락의 대부분은 구매 의도 단계)이 같은가"를 확인했다.

| 확인 | 바꾼 것 | 하락 기여도 1위 | 결론 | 쿼리 |
|---|---|---|---|---|
| 기존 | 시즌 11/23~12/18 vs 1/5~1/31, 최대 도달 기준 | 구매 의도 (67%) | | 30 |
| 퍼널 방식 | 엄격 기준 퍼널 | 장바구니 (69%) | 같음 | 30 |
| 기간 경계 | 시즌 11/27~12/18 vs 1/11~1/31 | 구매 의도 (94%) | 같음, 더 뚜렷 | 33 |
| 비교 기준선 | 시즌 vs 시즌 전(11/1~11/22) | 구매 의도 (162%), 다음 단계 −143% | 단계별 판정 불가 | 32 |

### 비교 기준선 확인에서 발견한 기록 문제
- 시즌 전의 구매 의도 → 결제 시작 전환율이 91.75%로 비정상적으로 높았음
- 확인 결과 시즌 전 결제 시작 세션의 91.7%에 장바구니 기록이 없음 (시즌·비시즌 약 29%) → 11월 초 add_to_cart 기록 누락
- 장바구니 기록 영향이 없는 "조회 → 결제 시작" 합산으로 비교:
  시즌 18.1% / 시즌 전 16.8% (−7%) / 비시즌 9.5% (−48%)
- 해석: 구매 의도 감소는 "시즌이 아니면 원래 낮다"가 아니라 연휴 직후 비시즌(비시즌)에 나타난 현상

### 아직 하지 않은 확인
- 분석 단위 변경 (세션 → 사용자 기준 전환율)

## 5. 방향 결정: 방향 C
- 비시즌 하락: 신규 방문자의 구매 의도·구매 금액 감소(계절 요인)로 짧게 설명하고, 평가 기준(평소 기준선 세션 전환율 1.0~1.3%)을 제안
- 개선안·A/B 테스트: 할인 기간 신규의 결제 정보 단계 이탈(전환율 41.9%)에 집중
- 이유: 고칠 수 있는 문제이고, 매출이 큰 시기의 누수이며, 대상이 구체적이라 실험으로 연결됨
